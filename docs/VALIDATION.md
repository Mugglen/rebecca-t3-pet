## 采集器停止后的恢复修复（同日）

- 现场：桌宠窗口进程仍在，采集进程已消失；最后快照停在本地 07:07:12。独立 `collector --once` 能重新读取 connected，说明当前 T3 数据源可用。旧版未保存退出原因，无法确定当时的具体触发事件。
- 已复现缺陷：状态文件原子替换超过约 120 ms 的局部重试仍失败时，旧连续采集循环直接返回 2，窗口不再重启采集器。现在持续模式保留旧文件并退避重试，窗口监控退出后重新启动；单次 `--once` 失败仍返回错误。
- **Python：64 项通过**，主代理完整复跑耗时 8.018 秒。新增失败/恢复、持续失败退避、日志限额与脱敏、双父进程守护和初始化清理；真实 Windows 文件共享锁测试持锁超过局部重试预算，确认同一采集进程存活，解锁后恢复写入。这是受控 demo 测试，不等于真实 T3 任务验收。
- **WPF：28 项通过**，主代理复跑结果在 `tmp/desktop-smoke-20261125-025750/`。**生命周期：36 项通过**，主代理使用本机 venv 复跑，结果在 `tmp/collector-lifecycle-20261125-025928/`；base Python 分支由实现代理验证 35 项（子进程数不同）。覆盖退避、启动失败、拒绝旧快照、清理实际 Python 子进程、停止后不重启、独立采集器不受影响及日志限额。
- **真实持续采集**：10:58 重启后收到 live/connected/working。精简日志在 10:58:41 记录一次真实 `PermissionError`（winerror 5），10:58:44 记录写入恢复，期间使用同一采集 PID。这证明本次运行中的写入失败已自动恢复，不能反推早上退出的确切原因。
- **真实自动重启**：10:59 仅终止本桌宠持有的采集启动器；窗口进程保持存活，生命周期日志记录退出码与新的启动，旧实际 Python 进程已退出，新快照再次为 live/connected/working，运行任务数 1。摘要在 `tmp/live-recovery-result.json`。未终止或修改 T3 服务。
- 窗口操作工具未列出该隐藏 WPF 桌宠，最终验证依据为进程、新快照和生命周期日志；不将它表述为界面目视验收。物理睡眠/唤醒与长时间运行仍待验收。
