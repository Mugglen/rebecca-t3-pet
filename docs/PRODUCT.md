# 产品与角色设计

## 用户已确认

> 我想让她作为 T3 code 运行状态的监控，就像 codex 的桌宠一样。

角色为瑞贝卡，外观选择 Q 版动漫风。

以下是用于启动开发的设计建议，不代表用户逐项指定了动作、状态优先级或技术实现。

## 首版体验

瑞贝卡以小型透明悬浮角色陪伴桌面工作。动作表达状态，简短气泡补充原因。默认安静，只有状态变化或用户点击时出现提示。

建议先监控本机 T3 环境中的活动任务；后续可增加指定项目或指定线程。远程环境不默认视为已接入。

| 状态 | 建议角色表现 | 提示内容 |
| --- | --- | --- |
| 空闲 | 轻微呼吸、眨眼 | 等待新任务 |
| 运行中 | 专注操作终端 | 正在运行的任务数量 |
| 需要你处理 | 招手或轻敲提示牌 | 有输入、确认或审批请求 |
| 刚刚完成 | 短暂得意或庆祝动作 | 本次任务完成；随后回到当前状态 |
| 失败 | 皱眉或举起警示牌 | 有任务失败，返回 T3 查看 |
| 已中断或取消 | 短暂停止动作 | 任务已停止，不作为成功庆祝 |
| 断连或无法识别 | 检查连接的动作 | 数据不可用或版本不兼容 |

多任务场景要保留计数和原因，不能只用一个“最近线程”覆盖所有活动。等待用户时优先提醒；其他优先级在状态机测试中明确。完成反馈只响应新完成事件，不能每次启动都庆祝历史任务。

运行状态与请求提示分开建模：异步问题可以在任务继续运行时显示“有待回复”，不应误画成任务停工。

## 角色方向

- Q 版动漫比例，以浅色双马尾、红色眼部、深色服装和荧光绿／粉色点缀建立识别度。
- 保留直率、有活力的表情；状态提示短而明确。
- 小尺寸下仍能区分忙碌、提醒、完成与失联。
- 采用透明背景的正式角色素材；素材来源、生成提示和加工步骤记录在项目内。
- 待机动作克制；提供暂停动画或安静模式。

当前 v0.1 使用透明角色图集和坐姿覆盖图，工作状态已加入六帧敲键盘 GIF，其他状态仍为静态姿势加整体动效，见 [资产生成记录](../assets/GENERATION.md)。上表的眨眼等细节是设计方向，不代表本版均已实现。另有六张候选形象供用户选择，选择前不改变默认显示。

## 桌面交互

- 拖动调整位置，右键提供状态详情、安静模式和退出。
- 点击显示当前摘要；仅在有可验证的跳转方式时提供返回对应 T3 任务。
- 多显示器和 DPI 缩放下不丢失角色；显示器断开后有回到可见区域的方法。
- UI 线程不承担阻塞的状态读取或网络请求。

## 首版验收

1. 发起真实 T3 任务，角色在目标 2–3 秒内进入运行状态；以实测结果确认刷新目标。
2. 出现需要用户处理的请求时提醒；仅等待后台任务时不误提示用户审批。
3. 任务完成只触发一次完成反馈；失败、中断和取消与成功区分。
4. T3 退出、数据源不可访问或结构变化时显示断连／不兼容，不显示“任务完成”。
5. 同时有多条任务时，计数和提醒可解释；重启不会重复回放历史完成通知。
6. 拖动、退出、透明区域命中和不同 DPI 下的位置经过实机检查。
7. 桌宠退出后不残留采集进程；新增文件与运行输出均位于 D 盘。

## 后续可扩展方向

指定项目／线程、点击跳转、托盘管理、更丰富的动作、可选声音。语音对话与独立聊天模型暂不在首版范围内。
